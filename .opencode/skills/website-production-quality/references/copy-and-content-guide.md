# Customer-Facing Copy and Content Reference

This reference supports the `website-production-quality` skill. Keep all choices contextual.

## Show an interface message only if it helps users

A message should answer one or more of: What happened? What is happening? What should I do next? What can I do if it fails?

Appropriate: “Your booking is confirmed.” (only after actual confirmation), “Payment couldn't be completed. Try a different payment method.” (if accurate), “No orders yet.”, “Image uploaded.”, “Saving…”

Inappropriate: “Booking module imported,” “Generated with Next.js,” “Successfully configured webhook,” “Site copied from TemplateCorp,” “Our agent has finished implementing responsiveness.”

## Keep technical details in the right place

- Developer-facing: commit messages, PRs, terminal output, internal diagnostics, engineering documentation, development-chat summaries.
- Customer-facing: tasks, features, benefits, options, plain-language errors, genuine status, accurate product disclosure.
- Intentional technical-user context: developer dashboards may appropriately mention tokens, API keys, environment status, sync origins, and service names.
- Compliance: show required legal notices, third-party attribution and licensing, truthful AI/material provenance, tracking/privacy/consent information.

## UI surface standards

| Surface | Rule |
|---|---|
| Hero / landing copy | Specific value proposition grounded in real product/service. No fabricated promises or “revolutionary” filler. |
| Headings / cards | Label actual information and user goals. Avoid redundant headings and generic benefit cards. |
| Buttons / CTAs | Clear verbs for real actions; no “Click here to experience innovation.” |
| Loaders | Short task status where waiting needs explanation. |
| Toasts | Confirm genuine outcomes; omit where interface makes result obvious. |
| Errors | State the issue in understandable terms, offer next step, preserve internal detail only in logs. |
| Empty states | Explain the current situation, offer a relevant action. |
| Forms | Accurate labels, field help, actionable validations. |
| Footer | Useful navigation, legal/contact details where provided/required; no development credits unless authorized. |
| Metadata | Accurate titles/descriptions, no stuffed keywords or invented awards. |
| Accessibility | Clear alt text, meaningful labels, no reliance on color or decorative text alone. |

## Common triggers to review in code search

Patterns or phrases such as `generated by`, `hosted AI`, `fully imported`, `copied from`, `cloned from`, `inspired by`, `powered by`, `integrated with`, `backend connected`, `API successful`, `production ready`, `as requested`, `lorem ipsum`, `placeholder`, `demo`, `elevate`, `unlock potential`, `seamless`.

**Do not blanket-delete matches.** Some technical disclosures, credits, or intentionally customer-visible terms are legitimate. Review their audience and legal context.

## Site type adaptations

- **E-commerce:** clear product/category info, shipping/returns only if verified, accurate stock and purchase states.
- **Booking:** truthful availability, pricing, guest rules, cancellation terms, confirmation states; no invented bookings.
- **SaaS:** accurate feature and billing descriptions, precise settings labels, informative errors.
- **Portfolio:** real work, accurate credits, no fictional clients/testimonials.
- **Healthcare / finance / legal:** especially precise descriptions; avoid fabricated guarantees or misleading claims.
- **Education / nonprofit:** inclusive accessible language, clarity about actual programs and impact.
- **Developer products:** real technical terminology is appropriate when it is part of the product, not a boast about how the site was built.

## Example: import work

Developer says: “Import the layout and assets from ReferenceSite and implement it under our own brand.”

Agent should:
1. Verify permitted asset usage and preserve required credits.
2. Adapt layout/content to the project's actual identity and user needs.
3. Not place “Fully imported from ReferenceSite” on the page.
4. Report which sections were imported and any licensing issues to the developer in chat.
