# Universal Website Quality Gate

Run these checks on work you touched before calling it complete.

## Content and truth

- [ ] No developer commentary, prompt echoes, import/copy/source announcements, debug output, or agent-work reports visible to the intended customer.
- [ ] No unearned AI-sounding filler or redundant self-congratulatory phrases.
- [ ] No made-up testimonials, metrics, reviews, inventory, services, prices, testimonials, certifications, partner logos, guarantee claims, or policies.
- [ ] No leftover placeholder copy unless it is intentionally isolated to development and not in customer-visible production output.
- [ ] Any necessary third-party credits, licensing, consent, and legal/AI disclosures remain intact and accurate.
- [ ] All copy matches the intended audience, locale, and established brand voice.

## Product behavior

- [ ] Feature functions, not only the visual UI.
- [ ] Loading, success, error, offline, empty, and permission states are accurate wherever applicable.
- [ ] Buttons and links perform their advertised actions; no dead-end interactive elements.
- [ ] Payment/booking/account status is grounded in actual state, not a fabricated success banner.
- [ ] Error descriptions are useful and don't expose secrets, raw tracebacks, or sensitive internals.

## Design and experience

- [ ] Consistent typography, spacing, hierarchy, button styles, components, and tone.
- [ ] Responsive from small mobile widths through desktop; no unnecessary horizontal scroll.
- [ ] Accessible semantic structure, keyboard navigation and focus, form labels, sufficiently readable contrast, and meaningful status announcements.
- [ ] No extra “AI-powered”, “new feature”, “premium”, or badge/chip decoration unless meaningful and authorized.
- [ ] No cross-brand styling or imported identity left behind.

## Verification and developer report

- [ ] Searched affected files/components for obvious red-flag phrases and reviewed matches.
- [ ] Ran available relevant checks and inspected rendered states where tooling permits.
- [ ] Reported completed work, checks, and limitations to the developer, not the user interface.
- [ ] Clearly distinguished verified facts from assumptions/unverified functionality.

If a check isn't possible, report that limitation. Don't mark it passed without evidence.
