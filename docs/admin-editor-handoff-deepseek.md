## Current implementation

- `components/admin/AdminDashboard.tsx`, `app/admin/page.tsx`, `app/admin/admin.css`: admin overview/navigation, mobile navigation, homepage editor entry and unsaved-change handoff. Check the actual diff before changing behavior.
- `components/admin/HomepageSections.tsx`: homepage section list, desktop HTML drag/drop, touch handle and keyboard-accessible up/down controls; select/hide/show existing sections; add up to eight validated custom message, FAQ and product sections; edit hero text/images, hero button text/links, design banner, existing product/contact headings, and custom section content; upload images through the existing authenticated media endpoint; select active catalog products; responsive iframe widths 375/768/1280; save, publish, discard and restore previous version. Message sections expose constrained background, text alignment and image position. Product sections preserve selection order. `HomepageQuestionsFields.tsx` adds editing of the existing FAQ, including optional internal links. This FAQ addition was in progress at handoff and needs the verification below.
- `lib/homepage-builder.ts`: versioned, backward-compatible layout model; fixed sections plus validated custom UUID sections; field length limits, safe internal links, media path validation, section uniqueness, and canonical parsing. `homepageStructure()` provides the baseline used for optimistic publish conflict detection. Extend this schema deliberately; old saved layouts must keep rendering unchanged. Never accept arbitrary HTML, CSS, JavaScript URLs, untrusted external images or unchecked IDs.
- `components/HomeContent.tsx`, `components/HomeSectionOrder.tsx`, `app/page.tsx`: shared storefront/preview renderer. The public homepage loads the published layout; absence of one preserves the original layout. Hidden sections are not rendered publicly. Keep product cards and catalog state truthful; do not manufacture inventory or sales claims. `app/kingdom-design.css` styles the controlled custom sections.
- `app/homepage-preview/page.tsx`, `components/admin/HomepagePreviewBridge.tsx`: authenticated, noindex preview. The same-origin iframe bridge validates origin, source, and layout before applying changes. It handles selection, inline edits, safe text insertion, previews/reordering/visibility, product cards and visible-root replacement during streamed loading. Preview-only DOM manipulation must never write data or run on the public homepage. Maintain the unsaved-edit guard, focus behavior, Escape handling, plain-text paste and editable-text length limits. Preview uses the actual storefront styles; its hidden product-card shelf may be expensive for large catalogs and deserves profiling.
- `app/api/admin/homepage-draft/route.ts`, `lib/homepage-layout-store.ts`: authenticated draft API, `site_settings` keys `homepage_layout_draft_v1`, `homepage_layout_draft_revision_v1`, `homepage_layout_published_v1`, `homepage_layout_previous_v1`; advisory transaction lock `kcp_homepage_layout_v1`. PUT/POST/DELETE use `expectedRevision` and return 409 on stale draft writes. Publication checks the saved draft, original content/structure, required fields, active products and uploaded media before transactional writes. Publish/restore update the legacy homepage setting keys and invalidate the homepage. Verify Cloudflare runtime compatibility before changing transaction, crypto or cache APIs.
- `app/api/admin/settings/route.ts`, `lib/catalog.ts`: existing settings saves use a baseline and the same advisory lock to avoid overwriting newer homepage text. Preserve the legacy settings workflow and conflicts.
- `components/HeroImageSlider.tsx`, `lib/hero-slides.ts`: preview hooks and validated uploaded hero image paths. Avoid exposing draft data publicly.
